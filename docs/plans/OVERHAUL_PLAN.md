## 1. Goals, non-goals, metrics

**Goals**
1. **45 v2 tools** (36 core) generated from one spec table, every op implemented end-to-end or explicitly `UNSUPPORTED` with a test.
2. **Core tools/list ≤ 45 KB** (vs ~100 KB for v1 today; ≈1.25 KB/tool flat-schema average — P3 measures the first 5 migrated tools and, if the projection exceeds budget, trims descriptions, never tools; if trimmed descriptions still project over budget, the lowest-use core tools by the §3.5 transcript mining move to an optional toolset, and any budget change is recorded with rationale in the progress log and re-gated), all toolsets ≤ 75 KB (golden + byte-budget test).
3. One result/error contract, one tier model, one param vocabulary — lint-enforced over the generated tools/list.
4. Nothing synchronous > 30 s; every tool has a declared, enforced timeout.
5. 28 packages, an enforced import DAG, one supervisor shared by stdio and daemon; daemon gets the cockpit.
6. E2E harness (T1 in-proc over **both** dispatch backends, T3 real binary over stdio + HTTP), ≥ 35 scenarios incl. ≥ 14 faults; merged coverage gates.
7. Clean root; generated docs; migration guide mapping all **155** v1 names.

**Non-goals**: new gameplay/authoring features beyond the *scoped new work* list in §2.7; implementing the 16 missing HUD ops (HUD effort; they re-enter via the spec table when their ops exist); C++ plugin changes (verified: no op names in `plugin/UnrealMCP/Source`; cockpit carries an opaque `manifest_digest`) — plugin README only; Linux/macOS editor support (CI still runs pure-Go tests on Linux). **Honest scope note:** §2.7's 12 items are real feature work, several only verifiable in a live editor (editor-aware `git_revert`, WP `loaded_cells`, PIE path translation, class resolver); P5c/P5d therefore carry live-editor risk that T1 cannot retire — they are re-checked in T4 and may slip to a v2.1 behind `UNSUPPORTED` if T4 fails, rather than block the release.

## 2. Target design

### 2.1 Tiers, annotations, gate

Five tiers; every **op** has a tier (`OpSpec.Tier`); a tool's tier = its worst op.

| Tier | Meaning | readOnlyHint | destructiveHint | idempotentHint | Cockpit gate (when policy=`require`) |
|---|---|---|---|---|---|
| ReadOnly | no state change | true | (omitted) | (omitted) | never |
| Ephemeral | UI/session state only (viewport camera, selection, toolsets, job cancel, server-owned scratch files) | false | **false** | per op (`OpSpec.Idempotent`, default false; tool = AND of its ops) | never |
| Mutating | changes project/world content, recoverable by the rollback ladder | false | **false** | false | never |
| Destructive | can lose user-authored content (deletes, overwrite-import, restore, revert, demolish, clear) | false | true | false | approve |
| Exec | arbitrary code (python, console, actor_call, headless) | false | true | false | approve |

`openWorldHint` explicitly `false` for offline tools (`analyze`, `design_*`, `git`, `toolsets`, `project_config`, `job`; `git_revert` is not offline — it talks to the editor, §2.5), `true` otherwise (SDK `*bool` omitted ⇒ true per spec — `protocol.go:1364,1377` — so we always set it). **Lint rules** (over generated tools/list): a ReadOnly-annotated tool contains only ReadOnly ops; annotations equal worst-op mapping; **a Destructive or Exec op may live only in a tool whose other ops are all ≥ Mutating on the same resource** (no destructive op hidden in a mostly-read tool).

**Declared tier ≥ derived tier (empirical lint).** `internal/tools/spec/pyops.go` assigns every Python op a tier (this table *replaces* `manifest/table.go`; e.g. `pie_exec`=Exec, `pie_set_property`=Mutating, `scene_clear`=Destructive, `actor_transforms`=ReadOnly). Each `OpSpec` declares `Reaches []string` — every PyOp it may dispatch, **including Go-side orchestration** (playtest beats, scene prune, health probes). Two tests: (1) static — `OpSpec.Tier ≥ max(tier(Reaches))`; (2) dynamic — the T1 emulator records the PyOps each (tool, op) call actually dispatched across all T1 scenarios and asserts `observed ⊆ Reaches`. A tier can no longer be declared lower than what the code can do. **Argument-dependent tiers:** `pyops.go` also records per PyOp `Escalations []Escalation{Arg, When any, Default any, Tier}` evaluated on the **effective value after defaults** (so default-on flags are caught — e.g. v1 `apply_level_recipe clean_slate` default True). A pytest parses each `_op_*` AST for `args.get(k, default)` and asserts the defaults in `pyops.json` match the Python, so a changed default can't silently disable an escalation (e.g. `widget_compose: {prune: Destructive, remove: Destructive}` — `mcp_bridge.py:2433`; `scene_apply: {prune: Destructive}`; `import_assets` is unconditionally Destructive). Lint: an OpSpec reaching an op with escalations must either declare ≥ the escalated tier or list those args in `Rejects` (server-side validation refuses them). Hence `widget_edit` = `compose` (rejects prune/remove, Mut) `| prune` (Destructive; carries prune/remove). P3a sweeps every `_op_*` **and every Go handler that touches files** (capture clear, snapshot store, scene/widget cleanup, revert backup) for flags matching `prune|remove|delete|overwrite|replace|force|clean|clear|reset|discard|purge|wipe|save` and for **unconditional** side effects with no flag (e.g. `_op_open_level`'s `save_dirty_packages`, `set_world_gamemode`'s save); each verdict (tier, escalation, or "write-only, not loss") is recorded in the progress log. Gating is **per op**: `widget_edit compose` stays Mut and is not gated even though the tool's annotation is Destructive (worst op). A pytest loads `pyops.json` (generated from `pyops.go`) and asserts every `_OPS` key appears exactly once.

**Gate policy** (`-gate-policy` / `.umcp.json`): `off` (default for unattended runs and when no cockpit browser client is connected), `require`: Destructive/Exec calls wait for approval **before** the op's deadline starts (the op `Timeout` clock begins only after approval). Sync tools: the approval wait is capped at `min(gate_timeout, 25 s)`; if still pending, the call returns success `{state:"pending_approval", executed:false, job_id}` with summary line "NOT executed — awaiting approval (job …)" and the op runs as a job once approved (`job wait`/`status`; denial or `gate_timeout` (default 120 s) ⇒ job `failed` with `PRECONDITION {reason:"denied"|"approval_timeout"}`). Async tools: approval is the job's first phase. Never a silent stall, never `TIMEOUT` caused by the gate. T1 covers approve-within-25 s, pending→approved, pending→denied, pending→timeout. `manifest_digest` sent to the plugin = SHA-256 of canonical (op, tier) list. Unclassified op ⇒ **test failure** (fail-closed at build time).

### 2.2 Design rules
- **R1** One tier per op; tool annotations = worst op (§2.1).
- **R2** `op` enums only where params are mostly shared, ≤ 8 ops/tool; flat schema (no `oneOf`); per-op required params validated server-side → `INVALID_ARGUMENT` listing them; description carries a one-line-per-op table.
- **R3 Vocabulary** (schema-lint enforced):
  `actor` — label, or object path (`/Game/…:PersistentLevel.Name`), or `@gamestate`/`@pawn` pseudo-targets where documented; ambiguous label ⇒ `CONFLICT` listing candidates (never first-match). `actors` for lists; globs only where documented.
  `class` — `/Script/Module.Class`, `/Game/…BP.BP_C`, or short name resolved by the §2.7 resolver (ambiguous ⇒ `CONFLICT`).
  `world` ∈ `editor | pie | auto`; **no global default** — per tool: `actor_edit` *requires* it; `actor_call` defaults `pie` (editor ⇒ `UNSUPPORTED` in v2.0, matrix §2.3); `console` ∈ `editor|pie`, default `editor`; `actor_query`, `reflect`, `world_query`, `snapshot`, `capture`, `screenshot` default `editor` (v1 capture/contact-sheet default) with `pie` explicit; PIE-only tools (`pie_*`) fixed `pie`; `auto` = pie if running else editor and is allowed **only on ReadOnly tools** (lint-enforced).
  PIE object paths: the resolver accepts editor paths in `world:"pie"` and maps them via the PIE package prefix (`UEDPIE_<n>_`), returning the resolved PIE path. Every world-aware result echoes `"world":"editor|pie"`. Python `_pick_world` renamed values (`game`→`pie`) and **raises `INVALID_ARGUMENT` on unknown values**.
  `asset`, `level`, `location`/`rotation`/`scale` = `[x,y,z]` (rotation = pitch,yaw,roll), `width`/`height`, `path` (filesystem input) / `json` (inline alternative), `timeout_s`, `wait_s`, `dry_run`. Properties match `^[a-z][a-z0-9_]*$`.
- **R4 Results**: `structuredContent` object (never bare array) + one text summary line. Images = `ImageContent` + `path`. Domain negatives are successes with explicit booleans (`met`, `pass`, `healthy`).
- **R5 Errors**: `isError:true` + `structuredContent {"error":{code,message,hint,retryable,outcome,details}}` + text `"[CODE] message — hint"`. Closed code set: `INVALID_ARGUMENT, NOT_FOUND, CONFLICT, PRECONDITION, PIE_NOT_RUNNING, EDITOR_UNREACHABLE, EDITOR_BUSY, OPERATION_FAILED, PYTHON_ERROR, UNKNOWN_OP, UNSUPPORTED, UNSUPPORTED_PLATFORM, TIMEOUT, CANCELLED, INTERNAL`. `outcome` ∈ `none|unknown` — `TIMEOUT`/`CANCELLED` on a non-ReadOnly op ⇒ `outcome:"unknown", retryable:false` (the editor keeps running the Python after uexec taints the channel, `uexec/command.go:86-127`). Hints for a known-but-disabled tool name: `PRECONDITION "tool X is in toolset Y — call toolsets enable Y"`.
  **Python→v2 code map** (original kept as `details.editor_code`): `ASSET_NOT_FOUND, CLASS_UNRESOLVED, TARGET_NOT_FOUND, NOT_FOUND → NOT_FOUND`; `NOT_IN_PIE → PIE_NOT_RUNNING`; `BAD_VALUE, PROPERTY_READONLY → INVALID_ARGUMENT`; `PLUGIN_MISSING → PRECONDITION`; `NOT_IMPLEMENTED → UNSUPPORTED`; `SPAWN_FAILED, IMPORT_FAILED, INPUT_FAILED, CAPTURE_START_FAILED, EDITOR_ERROR → OPERATION_FAILED`; `UNKNOWN_OP → UNKNOWN_OP`; exception w/ traceback → `PYTHON_ERROR` (traceback in `details` only). `_mcp_dispatch` changes: **any dict with an `error` key ⇒ `ok:false`** (using its `code` if present). pytest covers each mapping row.
  **SDK mechanics** (verified go-sdk v1.6.1): typed-handler Go errors become text-only `SetError` (`server.go:341-356`, `protocol.go:132-138`); input-validation failures likewise (`server.go:323-336`); a typed `Out` overwrites `StructuredContent` and output-validation failure becomes a protocol error (`server.go:359-391`). Therefore v2 registers every tool through **raw `Server.AddTool`** via the spec layer: in-house input validation (`github.com/google/jsonschema-go`, the SDK's own validator) producing enveloped `INVALID_ARGUMENT`; handlers return `(*CallToolResult, error)` where the spec layer always builds the envelope; **no `outputSchema` emitted in v2.0** (byte budget + avoids the zero-value overwrite; result shapes documented in `docs/tools.md`). A receiving middleware (`AddReceivingMiddleware`, `server.go:1352`) on `tools/call` (a) rewrites any `IsError` result lacking structured error into `INTERNAL`, and (b) catches `(nil, err)` from `next` — notably the SDK's JSON-RPC `-32602 unknown tool` (`server.go:743-751`) — and, when the name belongs to a disabled toolset, returns the enveloped `PRECONDITION` hint instead; truly unknown names stay a protocol error. The spec wrapper **`recover()`s per call** (the SDK has none; a handler panic would kill the daemon) → `INTERNAL` with the panic in `details`. `github.com/google/jsonschema-go` is pinned as a direct dependency at the SDK's version (v0.4.3). T1 asserts envelope shape on every error path: bad args, handler error, op error, timeout, panic, unknown op, disabled tool.
- **R6 Time** (per **op**, since tools mix sync and async ops — e.g. `editor_lifecycle reclaim` is sync while `restart` is async; `playtest list_scenarios` sync, `run` async): each `OpSpec` declares `Timeout`, `Max` and `Async` (Spec-level values are only defaults inherited by ops). Timeout enforced via ctx deadline; `timeout_s` override capped at the op's `Max`. Every sync op must have `Max ≤ 30 s` (test iterates all OpSpecs). Async ops return `{job_id,state}` unless `wait_s` (≤ 25 s) is given. **Progress notifications are emitted only during a `wait_s` window or a `job wait` call, against that call's own progress token**, and stop before its response (MCP spec). `jobs.Func` gains a `Progress(fraction, msg)` reporter; the job registry forwards to whichever call is currently waiting. **Jobs are owned by project** (canonical `.uproject` path), not by session or lease ID (daemon: pollable from any later session that attaches the same project; stdio: die with the process — documented). A project with a running job keeps its editor lease in state `draining` after its session ends (§2.6). Cancellation is tested server-side: handler sees ctx done → job `cancelled` → uexec channel tainted → reconnect on next call (the client never sees a `CANCELLED` response for a protocol-cancelled request; `CANCELLED` is returned only by `job cancel` results and to *other* waiters).

### 2.5 Snapshot store & rollback ladder
One store, Go-owned, file-backed: `<project>/Saved/MCP/snapshots/<name>.json` = `{taken_at, world, actors:[{path,label,class,tags,transform}], instances_digest?}` via the existing `actor_transforms` op (renamed `snapshot_actors`, extended with path/class/tags — §2.7). `diff a [b|current]` → added/removed/moved/retagged, **matched by object path** (label shown for readability). `digest` = the v1 scene_digest quantize+SHA1 (keeps `scope: instances|actors` and `class_filter`; read-only verify; does not create a snapshot). `snapshot_restore` restores **transforms of actors that still exist, matched by path** (v1 matched by label, `mcp_bridge.py:2866`); reports `not_restored:{added:[…], removed:[…]}` — description says so explicitly. **World Partition**: `get_all_level_actors` sees only loaded cells, so each snapshot records `loaded_cells` (WP) and `diff` reports actors outside the intersection of both snapshots' loaded sets as `unknown`, never `removed`; non-WP levels unaffected. The in-memory `level_snapshot` token mechanism is deleted.

**`git_revert` with a live editor.** Hazards (verified in UE 5.7 headers): the editor may write loaded/dirty packages back over reverted files; `ReloadPackages` defaults to *Interactive* mode (`PackageTools.h:19-28`) and would raise a modal dialog on the game thread; partially loaded packages hold write locks on their files (`FileHelpers.h:184`); reopening a dirty map can prompt. In-place reload is therefore **not** used. Procedure (async job, Destructive):
(1) compute reverted paths `git diff --name-only <cp>`; map `Content/**.uasset|.umap` → package names; (2) editor not running ⇒ go to (5); (3) query `packages_state`: loaded state of the reverted packages **and the full dirty set** (`get_dirty_content_packages` + `get_dirty_map_packages` — includes never-saved new assets and open-map edits unrelated to the revert); if no reverted package is loaded ⇒ (5) with the editor up (no locks, nothing to write back); (4) if any are loaded: **any** dirty package (reverted or not) ⇒ `PRECONDITION {dirty:[…all…], would_discard:[…]}` unless `discard_dirty:true`. Shutdown via the shared **safe-shutdown routine** (`supervisor.Shutdown`, also used by `editor_lifecycle restart`), remembering the open map — it first stops PIE if running, then **re-checks the dirty set immediately before quitting** (a package can become dirty after step 3: autosave tick, live coding, PIE stop); if the 30 s kill fallback fires without `discard_dirty`, the result reports `kill_fallback:true` + the dirty set at kill time: nothing dirty ⇒ **graceful** `unreal.SystemLibrary.quit_editor()` — the uexec channel drops mid-call by design, so EOF / `ErrOutcomeUnknown` on that call is treated as expected and success is confirmed by waiting for the PID to exit (kill after 30 s fallback; never surfaced as `EDITOR_UNREACHABLE`); dirty + `discard_dirty` ⇒ supervisor kill (a graceful quit would raise the save-changes modal); (5) **atomic file revert**: copy current versions of the paths to `Saved/MCP/revert-backup/<ts>/`, `git checkout <cp> -- <paths>`; on any failure restore from the backup ⇒ all-or-nothing; (6) if the editor was closed in (4), relaunch (every supervisor launch passes **`-AutoDeclinePackageRecovery`** — UE 5.7 `PackageAutoSaver.cpp:157,668-670`: declines the restore-packages dialog and removes restore files, so no kill/crash can bring back a modal; this applies to `ensure_open`, `restart`, crash relaunch and stdio auto-relaunch alike — today no launch path passes it, `internal/lifecycle`; note this also discards autosave recovery after a genuine crash — documented in operations.md, opt-out `.umcp.json` `keep_package_recovery:true` for hand-driven editors) and reopen the remembered map; (7) result: `reverted_files`, `editor_restarted`, `discarded_dirty` (every discarded package, reverted or not), `est_s` + hint `job wait` while running, `possibly_stale` (reverted packages not loaded while the editor stayed up — the directory watcher rescans them; agent should re-query `asset_query`), `rebuild_required` (true when `Source/**` or `*.Build.cs` changed — hint `build`). T4 cases: checkpoint → mutate+save → revert → `level open` → file hash == checkpoint; asset open in an editor tab during revert; unrelated unsaved new asset ⇒ `PRECONDITION` lists it; `discard_dirty` with the open map dirty ⇒ completes unattended, and `desktop_capture list_windows` after relaunch shows no modal (restore / save-changes / crash-reporter) window; same no-modal check after `editor_lifecycle restart discard_dirty:true` and after a forced crash → supervisor relaunch; `editor_lifecycle restart` with an unrelated unsaved asset ⇒ `PRECONDITION` listing it.

**Rollback ladder** (documented in `toolsets describe` + docs/tools.md): (1) `snapshot_restore` — transforms; (2) `scene_clear` — remove a tagged scene's actors then `scene apply` again; (3) `git_revert` to a `umcp/cp/*` checkpoint — files (assets/levels/C++), editor-aware as above. All three are core.

- **One Go peer per editor — hard rule.** UE's remote-execution node holds a single command connection; a second client steals it (already documented in-repo: `uexec/command_test.go:207-209`), and the cockpit plugin accepts one Go peer. A separate client port (6776 vs 6777) does **not** help — it is only our listen port (`uexec/config.go:18,56`). Therefore: during P0–P6, v2 runs **only** against the emulator or a dedicated editor instance no v1 consumer is using (e.g. a second editor on a scratch copy via `UMCP_PROJECT_DIR`); never against the user's working editor. **Connection-loss decision table** (single source of truth for retry, exactly-once and theft; evaluated in order by `uexec.Session`, policy from the dispatching `OpSpec` — the bridge call carries the OpSpec, not just the tool):

| # | Event | Action |
|---|---|---|
| 0 | Before sending **any** command on a channel idle ≥ 100 ms | liveness probe: `commandConn` keeps its `*bufio.Reader` (today only the `json.Decoder` over `bufio.NewReaderSize(conn,65536)` is retained, `command.go:25-26,64`); set read deadline **now + 3 ms** (a deadline of *now* never touches the socket in Go — `netpollcheckerr` returns timeout first, `runtime/netpoll.go:511-519`, `internal/poll/fd_unix.go:146-156`, `fd_windows.go:275`), `br.Peek(1)` (non-consuming), clear deadline. Timeout ⇒ alive, send. EOF/reset ⇒ dead, nothing sent ⇒ reconnect first (no outcome uncertainty). A peeked byte or `dec.Buffered().Len() > 0` ⇒ unexpected unsolicited data ⇒ taint + reconnect, logged as protocol desync. Whitespace-only peeked/buffered bytes (e.g. a trailing newline after a reply) are consumed and ignored, not treated as desync; T4 asserts no desync is logged in a normal live session. Residual race (editor closes after the probe) falls to cases 2/3. Windows timer granularity: if the cross-OS test flakes, widen to 5–10 ms rather than drop the probe; probe cost recorded in the P4 bench. Unit test on Linux + Windows: peer FIN detected within one probe; pending bytes left intact in the buffer. |
| 1 | Self-inflicted taint (our timeout / cancel, `ErrTimeout`, `command.go:181-186`) | mark tainted; reconnect on next call (as v1) |
| 2 | **Write** failed (non-timeout error) | at most a truncated frame reached the editor, which cannot parse or execute it ⇒ reconnect + resend once (any tier). A write *timeout* is case 1. |
| 3 | First peer close on **read** after a successful write | ReadOnly/idempotent op ⇒ reconnect + retry once; non-ReadOnly ⇒ return `ErrOutcomeUnknown` (`EDITOR_UNREACHABLE`, `outcome:"unknown"`, `retryable:false`), reconnect on next call. Discovery ping: different/missing node ⇒ editor restarted ⇒ normal relaunch logic |
| 4 | A reconnect fails **while the same node + project root still answer pings** (a different/missing node ⇒ restart/relaunch path, not theft), **or** a second peer close arrives ≤ 10 s after a successful reconnect while the same node + project root still answer pings | **stolen**: bridge state `stolen`; calls fail fast with `EDITOR_BUSY {reason:"channel_stolen"}` (+ `outcome:"unknown"` if a non-ReadOnly op was in flight); **no automatic reconnect** — only `editor_lifecycle reclaim` (explicit, logged; Ephemeral op) retakes the slot. No auto-reclaim timer (would fight a v1 consumer the user deliberately attached). |

A one-off editor-side hiccup with no second client therefore behaves like v1 (case 3), never as theft. Fakeeditor gains **`SingleSlot`** (default in emulator scenarios): an `open_connection` from a different source node closes the existing command connection, as UE does; a reconnect from the **same** node ID replaces its own old connection and is never treated as theft. Faults: editor not running → `EDITOR_UNREACHABLE` retryable; editor dies mid-call; reply slower than timeout → `TIMEOUT` + `outcome:"unknown"` on mutating + uexec usable after reconnect; protocol cancel → handler ctx done, job `cancelled`, channel tainted → reconnects; reconnect bumps generation → companion reinstalled exactly once; **channel theft** (two clients, one fake) → `EDITOR_BUSY`/`outcome:"unknown"`, never a wrong result; v1 companion resident → v2 install (and reverse); second cockpit peer refused → uexec fallback; Python exception → `PYTHON_ERROR`; malformed reply → `INTERNAL`; two daemon sessions × two editors, no cross-talk; **client vanishes without DELETE** (real `httptest` server; client connections force-closed incl. the standalone GET stream; SessionTimeout 200 ms and, separately, sweeper-only with a held half-open stream) → teardown runs, lease released, goroutines at baseline, session's `pending_approval` jobs cancelled; **exactly-once**: `DropAfterExecBeforeReply` on a mutating op → emulator executed it once, client `outcome:"unknown"`; same on a ReadOnly op → transparent retry succeeds; **stolen status + reclaim**: a `stolen` session's `editor status` reports `channel_stolen:true`; `editor_lifecycle reclaim` succeeds and the next call works; **case-folded adoption**: second attach with a path differing only in case adopts the draining lease; **client vanishes mid-job** → lease `draining`, other project cannot take the editor, same-project session attaches → adopts lease, `job status` finds the job, lease released after job ends; `project attach` changes deps + toolsets in a live session → list_changed; 200-session leak test (clean closes); gate: approve <25 s, pending→approved, pending→denied, pending→timeout; tier lint dynamic check (observed PyOps ⊆ `Reaches`) runs across the whole suite.

### 3.5 Tool-selection eval (P5e gate)
Purpose: prove consolidation doesn't hurt agents. Design: **60 tasks** (45 mined from aesir/poly-world session transcripts, 15 held-out hand-authored, incl. ≥ 6 that require `toolsets enable` and ≥ 6 multi-step author→play→verify) × **3 runs** × models `claude-opus-5-5` and `claude-sonnet-5-5` (IDs confirmed against the Models API in the pilot), **default temperature** (the 3 runs exist to measure variance), fixed task order seeds; each run is a real agent loop (max 12 turns) against the T1 emulator in **stateful-world mode** (`uexectest.World`: actors map with spawn/delete/transform/properties, PIE flag + PIE copies, assets map, snapshot files — so spawn→query→verify predicates are evaluated on real state, not canned replies). The same world model serves v1 and v2 surfaces. Scored per run: (a) correct first tool, (b) argument validity (server accepts, no `INVALID_ARGUMENT`), (c) end-to-end task predicate met. **Pass**: for (c) the v2 Wilson 95 % lower bound ≥ v1 mean, and (a),(b) v2 ≥ v1 − 2 pp; any v2 tool implicated in ≥ 3 failures is redesigned and re-run. Harness `cmd/tooleval` (deleted after release; results committed). Key from `ANTHROPIC_API_KEY`; tools/list prompt-cached. **Cost**: token volume is estimated in P5e from a 5-task pilot and presented to the user for approval before the full run; if declined, the gate runs only (b) offline via schema replay of transcript calls, and the progress log records the eval as reduced.

## 6. Risks & mitigations
| Risk | Mitigation |
|---|---|
| Capability silently lost | migration bijection (155 names); per (tool,op,world) T1 call; P0 harness on v1 first |
| Op-enum tools confuse agents | R1/R2 caps, destructive ops split out, §3.5 eval with pre-registered pass rule |
| Wrong-world / wrong-actor mutations | `world` required on mutating actor tools; result echoes world; `CONFLICT` on ambiguity; pytest + T1 |
| SDK envelope pitfalls | raw AddTool + own validation + safety-net middleware; T1 error-path matrix |
| v1/v2 collide on a shared editor | hard one-Go-peer-per-editor rule; v2 only on emulator / dedicated editor until P7; channel-theft detection → `EDITOR_BUSY`; `_mcp2` namespace for sequential handover; T1 theft + handover scenarios |
| Declared tier understates real behaviour | static `Reaches` lint + dynamic observed-PyOps check over the whole T1 suite |
| Revert undone by editor write-back | editor-aware `git_revert` (dirty check, reload/reopen, restart hint); T4 revert→open→hash case |
| Gate stalls an autonomous loop | approval before op deadline, ≤ 25 s sync wait then `pending_approval` job; default policy `off` when unattended |
| Leaked leases from vanished clients | `SessionTimeout` + kept sweeper + draining leases; vanish scenarios |
| Clients ignoring list_changed | static toolset config (flag/env/.umcp.json) |
| Live-only behaviour | §2.7 new work isolated & listed; rest is rename-only (diff reviewed as such); T4 before tag |
| Consumer breakage | consumers stay on v1 exe until P7; generated migration guide; rollback runbook drilled |
| Daemon per-session state bugs | session.State teardown via `ss.Wait()`; leak test; 2-session T1/T3 |
| Python split ordering bugs | byte-identical concat test before any edit |
| Eval cost | pilot-based estimate + explicit user approval; reduced offline fallback recorded honestly |
| Scope creep | non-goals + §2.7 closed list; gate reviewers instructed to reject additions |
