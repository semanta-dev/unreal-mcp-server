## Found and fixed live

| Finding | Fix |
|---|---|
| Slate events through `ProcessMouse*Event` never reached the button (`handled` was the viewport's or a pre-processor's) | events come from a **virtual Slate user** routed down an explicit widget path (as `UWidgetInteractionComponent` does), carrying the player's input device |
| Slate grants mouse capture only while the app is active: with the editor in the background a button's press took no capture and its release never clicked (`pressed_captured: false`, instrumented) | `SetHandleDeviceInputWhenApplicationNotActive(true)` for each synthetic event only, then restored |
| The game's cursor (cached by the viewport) was rewritten from the real mouse every frame it sat over the viewport | the agent's cursor is **pinned**: re-applied at every game tick's start (`OnWorldTickStart`) until `action=release` or PIE ends |
| A drag pinned its end, so the frame reading the press saw the wrong cell | the pin follows the drag from its start |
| A UI click's delayed release lost the button's hover/capture | a press a UI widget takes is released in the same call (Slate needs no frame); one the game viewport takes is released two ticks later (game input samples per frame) |
| `widget_edit op=compose` with a spec root that replaced `widget_create`'s `RootPanel` left the old root's variable GUID: 5.7 ensured on every compile ("was deleted but still has a GUID") and the plugin gate's health failed | widgets of the replaced tree are unregistered and reported in `removed` |
| Pointer results escaped `'` as `\'` (invalid JSON): a refusal became `BAD_VALUE` | built with the engine's JSON serializer |
| PolyWorld's HUD hit test read the **hardware** cursor (`FSlateApplication::GetCursorPos`), so with the real mouse over the minimap every world click was eaten as a HUD click | game-side: the HUD uses the player's cursor (`PC->GetMousePosition`), the one its world clicks deproject — [`polyworld-R2.patch`](../../plans/game-patches/polyworld-R2.patch) (scratch copy; the real repository after approval) |

Known limit: game code that reads the hardware cursor itself (as PolyWorld's HUD did) sees the user's mouse, not the
agent's — the agent never moves the OS cursor.
