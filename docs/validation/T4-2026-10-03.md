# T4 live validation — 2026-10-03

The checklist in [`operations.md`](../operations.md#validate), run against real Unreal Editor 5.7.4 instances
(Windows 11) with the v2 server from `main`. Every defect found was fixed and re-run live. Regression tests cover
every fix except two checked live only: the thumbnail lighting and the pre-flight's garbage collection (C++).
Fix commits: `841b80f`, `fe2c17c`, `98ff50b`, `a7bc8b0`, then the gate rounds `7820984` and `73358b7` (and the
commit that adds the round-3 notes). After `73358b7`'s build, row 10 (pre-flight, now its own `pie_preflight`
call) and project binding (segment-boundary matching) were re-run live on both projects (repeated on the final
build, output in `t4-2026-10-03/round2-*.jsonl`); the serialized restart
relaunches, the cancellable launch wait and the `pie: "requested"` result after a slow pre-flight are covered by
tests only.

## Setup

- **Projects**: full copies of `aesir-wave-defense` and `poly-world/PolyWorld` (content, C++ and binaries; not
  `Intermediate`/`Saved`/`DerivedDataCache`) in a scratch folder, each with its own throwaway git repo. Destructive
  checks (kills, crashes, reverts, rebuilds) never touched the real projects.
- **Isolation**: the copies use their own remote-execution multicast group (`RemoteExecutionMulticastGroupEndpoint=
  239.0.0.42:6799`, server `-group 239.0.0.42:6799`) and command ports, so a concurrently running agent session and its
  v1 server on the default group were unaffected.
- **Driver**: `cmd/mcpcall` (stdio, and `-url` against the daemon). The call scripts, scenarios and the daemon
  sessions' output are in [`t4-2026-10-03/`](t4-2026-10-03/) (`scripts/c*.jsonl` stdio, `d*.jsonl` daemon,
  `v1.jsonl`/`v2back.jsonl` the rollback drill); other results and returned images were inspected as each batch ran
  and are summarized below.

## Defects found live and fixed

1. **Wedged command channel.** After any timed-out call, every later call timed out until the server restarted: UE
   ignores `open_connection` from a node+endpoint it believes is still connected (`OpenCommandConnection`), and it had
   not noticed the channel we dropped. The client now sends `close_connection` before reconnecting to the same editor.
   The fake editor models the engine rule (`StickyConnection`).
2. **Stale companion.** A rebuilt server left the previous companion running in a live editor because the version
   number had not changed. The install sentinel now includes a source digest.
3. **PIE modal.** `pie op=start` froze the editor (and every remote command) behind "Blueprint Compilation Errors".
   Plugin pre-flight `PrepareBlueprintsForPIE` (compiles what PIE would, collects garbage, lists what its dialog would
   show, or acknowledges them); server-side: short pings, then the editor process's windows — the known dialog is
   cancelled with `WM_CLOSE`; other windows are only listed with the timeout, never touched.
4. **Build beside a hung editor.** One failed ping made `build strategy=ubt` run UBT next to the running editor
   (`LNK1104`). It now refuses while an editor of the project is alive (Windows).
5. **Checkpoint with a standard `.gitignore`.** `git add . ':(exclude)Saved'` fails when `Saved/` is ignored; excludes
   are now applied only for trees `.gitignore` does not already ignore.
6. **PIE transform of Static actors** reported success without moving; the PIE copy is made Movable, and a move that
   does not land is an error (before anything else changes). **Asset search** failed (`ARFilter` is
   constructor-only in 5.7) and searched `/Engine`; **tags** needed the object path.
7. **HighResShot output.** The recorder read `Saved/Screenshots` while HighResShot wrote a bare name under the
   engine's screenshot folder; **`screenshot op=pie`** reused one file name and could return the previous image.
8. **`game_scene` capture** looked for `unreal.EMCPCaptureCamera`; Python names the enum `MCPCaptureCamera`.
9. **Widget render** passed a Blueprint asset path where `LoadClass` needs the class; an older plugin without
   `CaptureWidget` raised a Python error (now `PRECONDITION` with `editor_code: PLUGIN_MISSING`). **Thumbnails** used a
   nonexistent light property and rendered the level around the mesh (now lit and isolated with a show-only list).
10. **World Partition + class filter**: a filtered snapshot dropped the unloaded set, so its diff reported an unloaded
    actor as `removed`; a filtered restore listed every other actor as `added`.
11. **Playtest beats**: `wait_until` polled with null arguments and never matched; `console` in PIE called
    `PlayerController.console_command`, which 5.7 does not expose.
12. **Daemon cold start** was tied to the attach call's deadline: the editor was killed while still loading. It now
    runs detached; attach returns a retryable `EDITOR_BUSY` and resumes on the next attach; a start whose session ended
    stays warm and is adopted by the next session of the project.
13. **Daemon bound the wrong editor**: a spawn selected a just-killed editor's lingering node (or another editor of
    the project) by path. Nodes known before the launch, and any answering with another pid, are excluded; cold starts
    of a project are serialized; attaching a project open in an editor the daemon did not launch is refused (Windows).
14. **Daemon restart** dropped the session's project and jobs (the restart's own job was "not found"); now only the
    editor is unavailable (`EDITOR_BUSY`, retryable), and build/revert/lifecycle/headless work is refused meanwhile.
15. **Gate round** (reviewers, then re-verified live): a session that ended mid cold start kept its editor leased
    forever (EndSession skipped unbound sessions); a finished start blocked attaching other projects; `asset_tags`
    failed during PIE (`find_asset_data` refuses in PIE; `get_asset_by_object_path` cannot take a string path in 5.7
    Python — now `get_assets_by_package_name`).
16. **HighResShot folder is configurable** (`GameScreenshotSaveDirectory`): every shot now gets an absolute name under
    `Saved/MCP`.
17. **Cross-project bind (stdio).** Re-verifying after a plugin rebuild, the server reconnected to the *PolyWorld*
    editor while aesir's relaunched (non-strict node fallback) and ran the next calls there. With `-project` set,
    selection is now strict: calls fail with `EDITOR_UNREACHABLE` until the project's own editor is back.

## Notes for deployment

- The real projects' `Plugins/UnrealMCP` copies predate `CaptureWidget`, `PrepareBlueprintsForPIE` and (PolyWorld)
  `MCPCore`. Until they are updated and rebuilt, `widget_query op=render` answers `PRECONDITION`
  (`PLUGIN_MISSING`), `pie op=start` relies on the modal guard, and the cockpit is unavailable.
- `capture source=game_scene` frames are dark on aesir's arena (scene captures have no eye adaptation); the
  `pie_highres` source matches what the player sees.
